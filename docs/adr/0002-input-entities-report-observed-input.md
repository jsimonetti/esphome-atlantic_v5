# Input entities report observed, not effective, input

The `input_i1` / `input_i2` entities publish the **observed input**: the physical state of the appliance's I1/I2 contacts as MAIN reports them, never the values a Rewrite substituted. In MITM mode the relay therefore hands the decoder the frame as it arrived and the wire the frame as rewritten, which is why `Relay::forward()` deliberately carries the pre-rewrite payload alongside the forwarded one instead of simply decoding what it sent.

The alternative — publishing the **effective input** MAIN acts on — was rejected because it destroys information: with `control_mode: boost` and a real PV inverter closing I1, the effective reading is `1` whether or not the inverter is there, and with `control_mode: off` a genuine PV signal becomes invisible entirely. The effective value is already implied by the control-mode entity, so reporting it again in place of the observed one trades a fact for a restatement. This is recorded because the code reads as a bug otherwise: a future reader finds the decoder deliberately fed pre-rewrite bytes and will be tempted to "simplify" it, and because entity semantics stop being reversible the moment someone builds an automation on them.
