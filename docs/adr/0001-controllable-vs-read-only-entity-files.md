# Only controllable entities get a dedicated L3 class

Only the `select` control-mode entity and the `switch` link-blackout entity get their own `atlantic_v5_select.h/.cpp` and `atlantic_v5_switch.h/.cpp` pairs, because they are the entities whose ESPHome-side action (`control()`, `write_state()`) must write into shared runtime state (`RelayPolicy` and `Relay` respectively). Read-only entities (sensor, binary_sensor, text_sensor) are populated purely by the hub calling `publish_state()` on native ESPHome objects registered through the generic table-driven codegen pattern, and need no custom class. If a future entity needs to write back into runtime state, it earns the same treatment; passive entities should not.
