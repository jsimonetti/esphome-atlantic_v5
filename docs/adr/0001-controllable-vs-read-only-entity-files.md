# Only controllable entities get a dedicated L3 class

Only the `select` control-mode entity gets its own `atlantic_v5_select.h/.cpp` pair, because it's currently the only entity whose ESPHome-side action (`control()`) must write into shared runtime state (`RelayPolicy`). Read-only entities (sensor, binary_sensor, text_sensor) are populated purely by the hub calling `publish_state()` on native ESPHome objects registered through the generic table-driven codegen pattern, and need no custom class. If a future entity needs to write back into runtime state, it earns the same treatment; passive entities should not.
